# ADR 0009: Audit runtime dependencies before releasing images
Status: Accepted and implemented · 2026-10-12

CI runs npm audit --omit=dev --audit-level=high after clean lockfile installation.
Known high/critical runtime advisories block validation and candidate promotion.
The initial full runtime audit was reviewed rather than treating build success as
security evidence. Auth’s compatible dependency refresh removes known advisories,
including [proxy-addr](https://github.com/advisories/GHSA-jqcg-44mw-7w3h).
Its exact IPv4 proxy trust configuration was not the mapped-subnet misconfiguration
described in that advisory; patching removes dependency exposure regardless.

Auth pins bcrypt6.0.0 to remove the old vulnerable node-pre-gyp/tar installer chain.
The [maintainer release](https://github.com/kelektiv/node.bcrypt.js/releases/tag/v6.0.0)
fits the existing Node22 runtime. A hash generated by the previous bcrypt5 image
authenticates under bcrypt6, with2a/2b prefixes and wrong-password rejection tested.
No account hash migration or password reset is needed. Gateway narrowly overrides
Swagger’s pinned js-yaml to5.4.3, preserving public MCP schema output.

Both runtime audits report zero vulnerabilities at launch. This does not promise
that future advisories cannot arise. Development-only dependency advisories remain
separate maintenance work; no broad forced toolchain upgrade was made. CI/public
OAuth/tool/revocation/restart checks verify functional compatibility before explicit
promotion. See [actual launch evidence](../production-execution-2026-10-12.md).
